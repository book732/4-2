# 요구사항 및 검증 기준

출처: 프로젝트 루트 `4-2.pdf`, 총 10페이지. PDF 안의 예시 결과는 이 프로젝트의 측정 결과가 아니다.

## 범위

제공된 `agent-leak-app`의 외부 관측으로 장애를 분석하고, OOM·CPU·Deadlock 리포트 3건을 PDF 또는 GitHub 저장소 형태로 제출한다. 제공 바이너리의 디컴파일·리버스 엔지니어링은 과제 범위에서 제외한다.

## 실행 조건

| 항목 | PDF 조건 |
| --- | --- |
| 환경 | Linux, 일반 사용자 |
| AGENT_HOME | 필수 |
| AGENT_PORT | 15034 고정, 0.0.0.0 바인딩 가능 |
| AGENT_UPLOAD_DIR | $AGENT_HOME/upload_files, 디렉터리 존재 |
| AGENT_KEY_PATH | $AGENT_HOME/api_keys, 경로 존재 |
| AGENT_LOG_DIR | 디렉터리 존재, 쓰기 가능 |
| MEMORY_LIMIT | 정수 50~512 MB |
| CPU_MAX_OCCUPY | 정수 10~100% |
| MULTI_THREAD_ENABLE | true/false, 1/0, yes/no |
| secret.key | $AGENT_HOME/api_keys/secret.key, 내용 agent_api_key_test |

## 필수 실험

| 케이스 | 변경 변수 | 필수 증거 | 완료 기준 |
| --- | --- | --- | --- |
| OOM | MEMORY_LIMIT | 시간별 RSS 증가, 종료 전후 앱 로그, 최소 2회 실행 | 임계값 변경 전후 종료 여부·생존 시간 비교 |
| CPU | CPU_MAX_OCCUPY | PID별 CPU 급상승, top/ps, Watchdog 종료 로그 | 임계값 변경 전후 종료 여부·생존 시간 비교 |
| Deadlock | MULTI_THREAD_ENABLE | PID 유지, 스레드 상태, CPU/RSS 정체, 마지막 대기 로그 | true/false의 정체·진행 여부 비교와 순환 대기 추론 |

각 실험은 한 변수만 변경하고 나머지 설정·관측 간격·최대 관측 시간을 동일하게 유지한다. 처음 제안한 환경값으로 특정 장애가 재현된다고 보장하지 않는다. 다른 장애가 먼저 발생하면 그 사실을 기록하고 실험 조건을 다시 설계한다.

## 해석 기준

- 애플리케이션 MemoryGuard 종료와 커널 OOM killer를 구분한다. 종료 코드만으로 발신 주체를 확정하지 않는다.
- 메모리 임계값 상향은 생존 시간을 늘리는 임시 조치이며 메모리 누수 해결의 증거가 아니다.
- CPU 제한값 상향도 연산량 감소의 증거가 아니다. 앱 내부 지표와 관제의 CPU 정규화 기준이 다를 수 있다.
- 낮은 CPU·정체된 로그만으로 데드락을 확정하지 않는다. 스레드별 점유·대기 자원과 순환 대기 근거를 제시한다.
- 관측 종료까지 살아있다면 생존 시간을 하한으로 기록하고, 종료 원인을 관측하지 못했다고 표시한다.
- 스레드 로그가 번갈아 나온다는 이유만으로 OS 스케줄러를 확정하지 않는다. 보너스 분석은 선택이며 추가 증거와 대안 가설이 필요하다.
